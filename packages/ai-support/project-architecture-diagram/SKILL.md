# 项目架构图

根据目标项目的代码和文档，将有依据的组件与关系绘制为可编辑的 `.drawio`，同时交付证据说明。

此 Skill 面向外部项目，可在具有文件读写能力的 Cursor、Qoder、Codex 等 Agent 中使用。完整目录可以独立复制，不依赖原始安装位置、其他 Skill、工作台源码或服务；产物可在 AI智图或兼容 draw.io 的编辑器中打开。

## 确定范围

- 以用户指定的项目为分析根目录；未指定时使用 IDE 当前业务项目，不把 Skill 所在目录当作目标项目。多个项目且无法确定目标时才询问。
- 默认画当前实现的模块架构总览。用户指定模块、链路、部署视角或目标方案时按该范围绘制，不擅自扩展成全仓库分析。
- 当前实现以代码和生效配置为依据；设计文档中的未实现内容标注为“规划”。仅有 PRD 或方案文档时仍可画图，但标题明确“设计方案”，不声称已经实现。
- 更新已有架构图时，先读取最新源文件，再结合项目证据修改。

## 读取项目并建立证据

按 [项目分析与证据](references/project-analysis.md) 读取项目约定、说明文档、构建清单、入口和相关实现，先确定模块边界，再沿调用、依赖、数据流或部署关系查证。

每个业务节点和关系记录图中 ID、仓库相对路径、可定位的行号或符号、证据类型。目录名和依赖声明只是线索，不能单独证明运行时调用。不要因为示例中存在网关、缓存或队列就在目标图中补上它们。

区分已证实事实、文档声明和推断。证据冲突在说明中列出；需要表达但尚未证实的节点或连线注明“待核对”，使用虚线并加入 `reviewItems`。无法支持的非必要关系直接省略。未经用户确认不要标记 `confirmed`。

## 生成文件

先读取 [文件格式与绘图规范](references/drawio-format.md)。可参考 [最小架构示例](assets/minimal-architecture.drawio) 的 XML 语法，示例中的内容不代表目标项目。

- 默认输出到目标项目 `docs/architecture/`，用户指定目录时遵从用户。文件为 `<主题>.drawio` 和同名 `<主题>.md`；PNG 为具备渲染能力时的附加交付。
- 一张图表达一种视角，用独立可编辑节点、真实父子容器和绑定端点的连线。大型项目先给总览，必要时拆成多个单页文件，不用一张密集类图替代架构总览。
- 新建源码架构图的 `generationMode` 使用 `manual`。这只是 Profile 1.0 的格式枚举，不代表没有 AI 参与；在 `provenance` 记录本 Skill 名和分析视角，不新增不兼容枚举值。
- 修改现有图时保留未涉及对象的 ID、几何、样式和折点，保留 `documentId`，更新相关证据；纯重新排版使用 `relayout`。语义变化使旧核对失效时恢复为 `needsReview`。
- 不修改业务源码或构建配置来配合画图。除非用户授权覆盖，已有输出使用新文件名；写完临时文件后再发布最终文件，避免交付半写 XML。

## 检查与预览

按 [校验与可选预览](references/validation.md) 使用当前环境可用的工具：至少尝试实际解析 XML，并检查 ID、父子层级、端点、几何和元数据；再对照证据检查语义。不能仅因为 XML 能解析就声称完整格式校验或架构正确。

有已安装的 AI智图 CLI 时可执行完整 Profile 校验和渲染；没有时仍交付源文件和证据说明，不要求安装工作台、启动服务或上传代码。PNG 只有实际渲染成功后才交付；能查看图片时检查文字截断、遮挡、方向和分组，修复发现的问题。自动修复最多三轮，仍失败则保留候选并列出错误。

## 交付说明

同名 Markdown 写入：图的范围与视角、分析基线（可用时记录 commit 和相关未提交变化）、节点与连线证据表、图例、待核对项及未覆盖范围。证据表格式见项目分析参考。

最终给出实际文件路径、核心结构说明、待核对项，以及实际执行的检查和结果。分别说明 XML 解析、结构检查、完整 Profile 校验、渲染、图片查看的完成情况；未执行项写明原因。没有命令或图片查看能力时如实说明，不把未执行当成通过。
