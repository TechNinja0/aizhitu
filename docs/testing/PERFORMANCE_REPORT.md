# 2026-09-22 性能优化与自测

本次针对常驻资源、含图片图稿编辑、自动保存和长期使用的存储增长完成优化。测试使用临时工作区和独立 Chromium，未调用真实 AI 服务。

## 改动

- 协同撤销/重做共用最多 100 条、32 MiB 的保守 UTF-16 字符串预算。超额时淘汰较远历史；单步自身超过预算仍保留最近一步，保证整图替换可撤销。预算是历史记录预算，并非整个页面的内存上限。
- 导出队列空闲 60 秒后关闭 Chromium，关闭期间的新任务等待回收完成再启动；已完成的下载结果不受影响。PNG/PDF 生成后清空输出页面并恢复小 viewport。
- 无并发冲突的协同保存复用已经校验的输入，跳过三方合并及第二次校验。并发分支仍保留三方合并、完整校验和事务；相同 XML 的比较直接返回。
- 服务器每份图稿最多 50 个版本、64 MiB XML 预算，至少保留最近两版。旧数据在该图稿下次有效保存时补齐字节统计，不在启动时扫描所有图稿正文。
- 协同回执仅在超过 24 小时、且结果版本已经早于所有可用基线时清理；这种过期请求重发会被拒绝，不会重新应用旧修改。仍可重放的基线对应回执不会因时间到期被删除。
- IndexedDB 升级到版本 2，草稿元信息与正文分开。恢复列表仅加载摘要，点击恢复按键才读取正文；最多 20 份、每图 3 份、40 MiB，按 30 天及容量淘汰旧记录；最新一份超额仍保留。升级逐条迁移，保留当前和前一份正文。
- 文件库前台 3 秒、后台 30 秒刷新，回前台立即刷新。AI 面板关闭且无任务时停止周期查询；运行时钟只在面板可见且有任务时更新。定时任务完成后才安排下次执行，避免请求堆叠。

## 同一图稿的前后实测

使用包含一张 600×600 合成 PNG 的 1.579 MiB 图稿，修改普通节点颜色 100 次；每个内存采样点均先触发浏览器 GC。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 初始编辑器 JS 堆 | 11.57 MiB | 11.57 MiB |
| 修改 10 次 | 44.32 MiB | 28.52 MiB |
| 修改 50 次 | 172.21 MiB | 30.03 MiB |
| 修改 100 次 | 331.80 MiB | 31.64 MiB |
| 清空协同历史后 | 15.80 MiB | 15.90 MiB |
| 单次协同保存，5 次均值 | 126.80 ms | 81.28 ms |

100 次修改后的 JS 堆降低约 **90.5%**，同一样本保存耗时降低约 **35.9%**。大图保留下来的最后一步撤销/重做均通过。计时包含校验、同步 SQLite 写入和版本维护，不包含 HTTP 与前端开销；有限采样不是所有图稿的性能保证。

导出队列空闲 62 秒检查时，Chromium 已自动关闭，测试进程树 RSS 由导出后约 1415 MiB 降为约 166 MiB。随后重新导出成功。多进程 RSS 可能包含重复统计的共享页；这一数字不等同独占物理内存。

小图编辑页空闲 12 秒仅有 3 次状态检查、没有提交；关闭的空闲 AI 面板 16.5 秒无周期请求，重新打开立即刷新。页面运行时错误为空。

## 边界

无冲突保存已经减少同步工作，但 XML 校验、并发三方合并和 SQLite 写入仍在 Node 主线程执行；没有引入 worker 架构。当前 1.579 MiB 样本保存约 81 ms，多人编辑更大文件仍可能有延迟。容量预算允许一份超大草稿、一次超大撤销及至少两份服务器版本，所以不是严格的整机内存/磁盘上限。

运行中的旧服务不会热更新服务器逻辑。完成编辑并确保图稿已保存后，重启原有服务、刷新已有工作台页面，服务端回收与保存优化才会完整生效。当前生产进程未在自测中中断。
