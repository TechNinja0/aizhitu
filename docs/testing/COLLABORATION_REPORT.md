## 新增协同验证

服务端与纯合并逻辑：

- 不同节点文字、同节点文字与位置可并发保留；同属性后提交胜出。
- 命名样式边界保持，独立填充色和边框色修改同时保留。
- 条件撤销保留别人修改过的属性。
- 删除优先于迟到的编辑，关联边清理后仍通过文档校验。
- 并发父子关系成环会拒绝，不部分写入图稿和版本。
- 两个 SQLite 连接同时使用同一工作区，协同与独占模式互斥。
- 会话 token 不能跨账号、跨文档使用，在线成员响应不包含 token。
- 请求 ID 与摘要保护重复提交；重启后以及基线淘汰后，已提交请求仍可幂等重试。
- 未被确认的旧基线超过最近 50 版时拒绝自动覆盖。
- 并发改名不会被未改名的旧页面回滚；伪造文档身份、脚本标签、无效图稿无法写入。
- 分享撤回删除会话，重新授权不能复活旧 token；退出账号撤销协同会话。

两个独立浏览器账号的真实画布操作：

1. 同时加入同一文档，看到对方在线。
2. 拦截写请求，让两端从相同基线编辑不同对象，然后释放请求，验证双方内容均保留。
3. 甲撤销、重做自己的编辑，乙的修改保留。
4. 远端更新后甲的缩放与选区保持。
5. 延迟已提交请求的响应，在此期间继续输入，确认追加修改不会被响应覆盖。
6. 服务端已经接受请求后中止浏览器响应，验证重试不新增重复版本，并保留乙后续修改。
7. 将甲的浏览器上下文设为离线，两端继续修改；恢复网络后自动合并。
8. 甲持续处于文字输入状态，乙编辑另一节点，甲的输入框不被同步强制关闭。
9. 两端同时改同一文字属性，控制请求先后顺序，确认最终都采用后提交值。
10. 两端同时复制新增节点，最终保留两个不同 ID 的新对象。
11. 所有者收回分享，被撤权页面暂停协同并禁止修改命令。
12. 退出协同后重新获得原独占编辑权。
13. 全程无未捕获浏览器 JavaScript 异常。

浏览器运行产物保存在被 Git 忽略的 `artifacts/collaboration.png` 和 `artifacts/collaboration-e2e-report.json`；重跑测试可重新生成。

## 测试中发现并修复

- Express 对绝对路径中隐藏目录的默认过滤导致 `.codex/worktrees` 中的画布页面和图标 404。仅对代码内固定的资源文件允许隐藏祖先目录，静态目录的隐藏文件策略仍保持禁止。修复后完整画布 E2E 通过。
- 协同期间文本输入也需要续约在线会话，已将心跳安排在输入状态检查之前。
- 保存响应可能晚于后续编辑，已引入发送快照作为 rebase 基线；重试沿用请求 ID。
- 用户退出协同时可能有同步在途，现等待现有流程并冻结画布后完成最后提交。
- 已同步时页脚可能继续显示旧的未保存提示，已使协同状态同步更新页脚。

## 2026-09-21 分享读写权限与查看/编辑切换

本轮完成上轮三个待对齐问题，并增加接收者默认查看、主动切换编辑的交互：

- 分享提供仅查看、可编辑，指定成员逐人授权，所有成员统一授权。新分享默认只读；已有分享首次迁移保留编辑权，后续启动不重置。服务端对协同、旧编辑锁/保存、恢复历史和 AI 请求校验编辑权。
- 所有者默认编辑，接收者和管理员打开他人图稿默认查看。查看页不创建协同会话，只按版本读取更新；可编辑成员点击右上方“编辑”加入，再次点击先保存再退回查看，按钮用深绿色表示选中。
- 只有编辑会话参与整稿操作占用保护。查看者不阻止作者恢复历史或删除，且能够收到恢复结果；删除后查看页停止显示文件。文件列表显示当前账号的“仅查看 / 可编辑”权限。
- 编辑授权收回立即清除服务端会话及兼容旧锁；无未同步修改时自动回到查看，有待保存内容则暂停并允许下载副本。
- 已保存文件通过新建、打开切换文件时，先完成服务器同步；失败留在原文件，重试成功后才切换。
