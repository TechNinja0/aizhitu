# 多人同时编辑技术方案

实现日期：2026-09-20；自动协同流程更新：2026-09-21。适用于当前单画布 `.drawio` 图稿、单个局域网工作区服务及 SQLite 数据库。

## 目标与现有基础

项目已有 draw.io 31.4.6 内核、React 工作台、Express 本地服务、固定账号、文件分享权限、SQLite 事务、最近 50 个服务器版本、浏览器恢复草稿。原有 `leases` 模型只允许一个页面写入，其他页面每 2 秒读取保存后的新版本。

现有文件区分查看和编辑：所有者默认编辑，分享接收者（含管理员查看他人文件）默认查看；有编辑权限的成员主动切换后加入协同。同一文档允许多个可编辑成员、同一账号的多个编辑页面同时编辑；正常网络下有待提交内容或前台多页在线时约每秒检查同步；提交的结果由服务器验证并持久化。前端移除独占锁轮询与申请/释放编辑权入口，使用“编辑”切换按钮控制本页模式。旧锁 API 仅保留服务端兼容，旧客户端锁与协同会话在数据库事务中互斥；新版历史恢复和删除通过协同 token、当前版本及在线页面检查执行。

## 行业参考与选型

- [Figma：多人协同技术](https://www.figma.com/blog/how-figmas-multiplayer-technology-works/)：图形文档按对象及其属性组织，服务端决定同属性更新的顺序；对象 ID 需要在客户端唯一生成，父子关系必须防止成环。这里采用其服务端排序、属性级合并的原则。
- [Yjs 官方介绍](https://docs.yjs.dev/)：共享数据类型和 CRDT 适合需要多副本合并、富文本绑定的应用。当前项目没有 Yjs 与 mxGraph 的绑定；把整份 XML 放入单个共享字符串仍无法获得对象级协同。
- [draw.io 嵌入接口](https://www.drawio.com/docs/reference/embed-mode/)：支持宿主页与编辑器通信。项目已有隔离 iframe 与自有 adapter，本次在此适配层增加协同合并和撤销处理，上游 vendor 资源保持原样。

| 方案 | 对当前仓库的影响 | 结论 |
| --- | --- | --- |
| 整稿最后写入覆盖 | 改动少，但不同节点修改也会互相覆盖 | 不采用 |
| 保留独占锁 | 无法满足同时编辑 | 仅保留服务端兼容，新版 UI 不使用 |
| 自行实现字符级 OT | 需要转换文本操作，还需另建图形对象协议 | 当前不采用 |
| Yjs + 对象模型绑定 | 需要替换状态源、构建 mxGraph binding、迁移持久化和撤销 | 后续富文本或离线优先版本再评估 |
| 服务端排序 + 对象属性三方合并 | 可复用现有 XML、认证、SQLite 和版本系统 | 本次实现 |

这是针对现有图形编辑器的集中式协同协议，不宣称为通用 CRDT。网络传输复用 HTTP，按 1/5/10 秒自适应轮询元信息，仅在修订号变化时返回完整 XML。这样可以复用 Bearer 鉴权、反向代理和已有部署。没有引入 WebSocket、Redis 或新的 npm 依赖。当前同步粒度是一次完整画布快照中的属性差异，不能据此承诺 60fps 光标同步或毫秒级反馈。

## 用户流程与边界

1. 所有者使用“分享链接”设置“指定成员”或“所有成员”；仅复制链接不授权。
2. 所有者打开即接入编辑会话；他人分享默认查看，只有 `canEdit` 为真才显示“编辑”按钮，点击后加入会话，再次点击先完成同步再离开会话、切回只读。初次网络失败自动重试，无访问权限则不显示图稿。导入或首次保存后的图稿也走同一路径，移除旧的 `zhitu-edit` 页面标记。
3. 状态栏保留分享范围、当前模式或编辑者、保存结果。单人编辑显示“编辑中”；多人直接显示姓名与“正在编辑”，当前账号标注“你”，不再叠加人数或单独的当前用户名。同账号多页合并一人并注明页面数。查看态显示“仅查看”，也展示实际在线编辑者，自己不计入。超过三人时收起其余姓名，悬停显示完整名单与页面数。分享范围简写“已分享”，具体范围与版本移到悬停说明及对应窗口。最多 32 个同时在线编辑页面。
4. 修改约每秒自动同步，状态栏显示连接/同步结果，不再显示手动保存按钮。选区、缩放和文本输入不因收到远端内容而被强制结束。
5. 返回文件库、新建 / 打开其他文件及退出编辑时冻结画布与标题、提交文字并等待在途请求及最后同步，成功后才切换；失败留在页面。恢复历史或编辑页删除要求没有其他在线编辑页面；文件库批量回收要求相关文件没有编辑页面。查看页不阻止这些操作。

同一文字节点的标签作为完整属性合并，不做逐字符 OT/CRDT。两个人同时改同一个标签时，以后提交到服务器的值为准。图片、核对元数据、路径点等不适合简单拆分的字段按完整值或结构处理。暂不提供远端光标、逐字符编辑光标、离线多端自动发现、跨服务器房间调度和多人操作时间线。

## 数据模型与模块

| 模块 | 职责 |
| --- | --- |
| `packages/editor-adapter/collaboration.js` | Node 与浏览器共用的三方 XML 合并、结构检查和内容等价比较 |
| `packages/editor-adapter/adapter.js` | 本地唯一 ID、协同撤销栈、远端状态应用、保留选区与缩放 |
| `apps/workbench/src/Collaboration.tsx` | 同步状态机、在途提交、重连、在线成员、退出与错误提示 |
| `apps/local-server/shared/collaboration.ts` | 会话、互斥检查、事务提交、幂等回执、最终验证 |
| `apps/local-server/shared/routes.ts` | 复用现有认证链路的协同 HTTP 接口 |

SQLite 新增两张表，启动时使用 `CREATE TABLE IF NOT EXISTS` 平滑创建，无需改变已有图稿格式：

- `collaborators(documentId, client, owner, name, token, expires)`：主键为文档与页面 ID。随机 token 绑定文档、账号和页面；30 秒无心跳即失效。读取在线成员不暴露 token。
- `collaboration_receipts(documentId, owner, requestId, fingerprint, revision)`：主键为文档、账号、请求 ID。记录请求规范化内容的 SHA-256 摘要和提交修订号，用于重试去重。回执与图稿及版本在同一事务中落盘。

`documents` 仍是服务端当前状态；`versions` 保留最多 50 次有效内容或名称变更，并受 64 MiB XML 容量预算约束；至少保留最近两版。协同每次有变化的保存记为“协同编辑”。仅视口变化、相同内容重传和幂等重试不创建版本。

## 合并协议

一次请求包含 `revision`（客户端确认的基线修订号）、`xml`（本次发送时的完整内容）、`name`、随机 `requestId`、会话 `token`。客户端不提供可信基线 XML；服务器根据 `revision` 从版本表读取自己的基线。

在 `BEGIN IMMEDIATE` 事务内：

1. 验证当前账号对文档的编辑权、文档未删除及协同 token 未过期。
2. 使用现有 document-core 校验提交内容：文档 ID、对象数量、XML/图片大小、标签安全、几何、父子关系、边端点等。
3. 查找回执：同请求 ID、同摘要返回最新服务器文档，不重复应用；不同摘要返回 409。
4. 获取基线 B 和当前服务器文档 R，对提交 L 计算 `merge(B, L, R)`。
5. 再次完整校验合并结果，通过后写文档、版本和回执，提交事务后响应。

合并细则：

- 按 root 下稳定的对象 ID 对齐，而不是对 XML 字符串做行合并。
- 本地未变化的属性保留 R；本地变化的属性写入 R。同属性双方都改了，服务端后处理的提交胜出，并返回冲突字段提示。
- 普通属性、几何属性分别比较；样式保持命名样式边界，仅在对应块内合并 `key=value`，避免改变 draw.io 样式含义。
- 新对象使用 `co-<页面UUID>-<模型序号>` ID。不同内容争用同一新 ID 时拒绝整个事务。
- 删除优先于迟到的属性更新，不允许旧修改重新生成远端已删除的对象；清理不存在父对象的后代、引用已删除端点的边和失效核对项。
- 已改变的节点或关系不能继续沿用旧的“核对确认”。
- 本地确实调整了既有对象顺序时，应用本地顺序，同时保留远端新增对象。当前不实现 fractional indexing。
- 父子成环或校验失败，整次提交回滚。客户端保留修改并暂停同步，用户可下载副本或放弃修改后重新加载。
- 名称单独合并：本页未改名则保留服务器名称；双方都改名时以后提交为准。

例如基线有 A、B 两个节点，甲改 A 的文字、乙改 B 的文字，最终保留两个修改。甲改 A 的文字、乙改 A 的 x 坐标，同样保留两个修改。甲乙都改 A 的文字时，只保留后到服务器的完整文字值。

## 客户端同步与撤销

客户端分别保存“已确认基线”“一个在途请求”“已收到但尚未应用的响应”。每页最多一个同步流程在运行，返回/历史恢复/删除触发的最终同步会等待现有请求完成。在线成员心跳在输入文本期间也会续约。

调度策略由 `collaboration-policy.ts` 定义：待同步内容（dirty、pending、received）优先使用 1 秒；干净的前台多页 1 秒、前台单页 5 秒、后台 10 秒。页面保留轻量定时检查，仅到期才发出网络请求。收到 `visibilitychange` 回到前台或 `online` 时立即检查；失败沿用原有退避。手动最终同步不受这些间隔影响。无本地修改时不再请求 iframe 快照与 XML 比较，但远端新版本仍正常合并。文本编辑事件会标记 dirty，输入期间继续心跳，结束后再提交。

分享权限保存后即时更新本页范围标记并提前检查服务端状态。`documents.shareRole` 保存所有成员的角色，`document_members.role` 保存逐成员角色（`view` / `edit`）；`canEdit` 由服务端按当前账号计算。新的分享默认 `view`，旧分享首次迁移为 `edit`；省略角色保留已有授权，新加入成员继承文档角色。读取正文、状态及列表摘要均返回 `canEdit`。

查看页只调用文档 `/state`，版本变化才取正文，不调用 `collaboration/join`，也不续约编辑会话。前台有编辑者时约 1 秒更新，没有编辑者时 5 秒，后台 10 秒。升级权限仅让编辑按钮可用，不自动进入编辑；降权清除会话与旧锁，服务端对协同保存、旧接口保存、历史恢复与 AI 请求均验证编辑权。干净页面自动退回查看，存在待同步内容则暂停并允许下载副本。

请求发送期间仍可编辑。响应到达后，在 iframe 内原子执行 `merge(发送快照, 现在画布, 响应文档)`，保留发送之后产生的新修改。只有画布内容和名称都与确认文档一致时才显示已同步。文本输入或鼠标拖动进行中，先暂存响应，等操作结束再合并。远端更新保持缩放和仍然存在的选中对象；更新对象模型后刷新 UI 统计。

协同使用单独的本地撤销栈，最多 100 次本页操作。撤销只反向修改本页那次操作涉及的属性；如果远端已把同属性改为另一个值，则不覆盖远端值。redo 的基线按实际撤销结果重新生成。远端状态不会被压入本地撤销栈。重新连接或恢复历史后重置协同基线并清空专用撤销栈，本地临时画布继续使用原生 undoManager。

## 故障、权限与持久化

| 情况 | 行为 |
| --- | --- |
| 首次连接失败 | 保持只读，网络失败约 3 秒后重试；权限或输入错误需处理后重新连接 |
| HTTP 超时、网络失败或服务暂时不可用 | 保留当前画布与原请求 ID，以 1、2、4、8、15 秒上限退避重试，允许本页继续编辑 |
| 已落盘但响应丢失 | 重试命中持久化回执，返回当前状态，不再次覆盖后来修改 |
| 会话超过 30 秒 | 重新加入后使用新 token 重发原请求；不擅自重置未同步基线 |
| 服务重启 | SQLite 保留文档、版本与回执；会话未过期则继续，过期则重新加入 |
| 基线超过最近 50 版 | 返回 409，停止自动写入，保留本地内容，要求先下载副本再重载 |
| 分享撤回、账号退出/停用/改密 | 服务端撤销相关会话；每次请求仍检查当前认证和文档授权，浏览器暂停并只读 |
| 关闭页面 | best-effort keepalive 退出；异常退出靠 30 秒过期清理 |
| 浏览器刷新或关闭导致内存队列丢失 | 沿用“恢复草稿”保存的浏览器副本及关闭前未保存提示；不会盲目将草稿覆盖到服务器 |

浏览器草稿不是协议回执日志。自动重试只保证当前页面存续期间的队列；不承诺崩溃刷新后自动续传。离线时应保留页面，或先“下载副本”。恢复草稿进入新图稿流程，可核对后另存。

编辑页删除、版本恢复接受 `collaborationToken` 与期望 `revision`。在同一个 SQLite 写事务内检查调用者有效会话、版本以及没有其他在线编辑页面（同账号的另一个编辑标签页也算其他页面），然后原子写入并记录版本。删除另外校验所有者/管理员权限并清理文档会话；恢复后保留当前会话。旧 `lockToken` 调用路径仅用于兼容。文件库显示协同占用状态并禁用批量回收选择。权限管理由所有者或管理员执行，不需要等协同结束；在线参与者不能借协同 token 绕过访问范围。

## API

统一前缀 `/api/documents/:id/collaboration/`，均为 POST，使用现有 Bearer 认证及文档权限中间件。

| 路径 | 输入 | 输出 |
| --- | --- | --- |
| `join` | `client` | `token, document, members` |
| `state` | `token, revision` | 续约后的 `document, members`；修订号相同时省略 XML |
| `sync` | `token, requestId, revision, xml, name` | `document, conflicts, duplicate` |
| `leave` | `token` | `ok`；退出可重复调用 |

错误码：400 输入不合法；401 认证失效；403/404 无权访问；409 基线、对象结构或请求 ID 冲突；422 XML 或合并结果不合法；423 会话失效或编辑模式互斥；429 房间页面数超过上限。AI 生成接口接受 `X-Collaboration-Token`，并复用协同文档授权；AI 候选应用仍经过已有本地基线检查，之后进入同一协同保存路径。

整稿接口：`POST /api/documents/:id/versions/:revision/restore` 与 `POST /api/documents/:id/trash` 的新版请求体为 `{ revision, collaborationToken }`。发现其他编辑页面返回 423；版本过期返回 409。此保护必须在服务端执行，不能用按钮禁用替代。

## 运维与演进

现有部署和备份方式继续适用：单 Node 服务、SQLite WAL、工作区数据库备份。无需对公网开放新端口。更新时先让成员通过“← 文件库”完成保存，重启服务；新表由应用自动创建。回滚代码前同样要求所有协同成员退出，避免旧版服务看不到新增会话而放行独占写入。

限制与容量：本次功能验证覆盖少量浏览器与 SQLite 多连接，32 是保护性准入上限，不是已验证的并发容量承诺。完整 XML 上传、对象模型刷新和逐次快照保存会增加大图成本；正式扩大团队前应针对实际文档测量合并耗时、事件循环延迟、网络流量和数据库增长。持久化回执目前不自动裁剪，以保证旧请求幂等；长期高频使用需要监控数据库体积。

后续若需求增长，优先把变更传输升级为显式属性操作及增量通知，保持 revision/幂等/验证边界；再引入文档房间分片、版本压缩及有明确定义的回执保留窗口。只有需要逐字符富文本和离线多副本长期合并时，才推进 Yjs binding，不能简单把整稿 XML 包进 CRDT 字符串替代当前逻辑。
