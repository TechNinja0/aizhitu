# AI 友好图形编辑器：产品需求与方案设计

版本：v0.3 · 日期：2026-09-18 · 状态：待用户审核，尚未进入实施

本次补充竞品调研：参见 [竞品调研与能力建议](2026-09-18-ai-diagram-competitive-research.md)。当前建议先评估复用成熟编辑器和文件格式；自定义 JSON 是候选方案，不再作为默认前提。新增功能均在调研文档中标记为待确认建议。

## 1. 产品定位与确认记录

面向个人开发者及少量技术同事的结构化图形编辑器。用户将流程图或系统架构图截图交给 Codex、Qoder 等外部 AI，生成可编辑图稿文件，在本地网页中继续编辑、保存，导出用于文档与分享的图片或 PDF。

已由用户确认：

- 首版服务个人或少量技术同事。
- 采用本地运行的网页，通过浏览器编辑、本地文件交换。
- 聚焦流程图与系统架构图。
- 支持忠实还原、重新排版两种生成模式，默认忠实还原。
- 采用结构化图形编辑器路线。
- 分阶段对接 AI：首版通过文件，后续支持直接操作画布。
- 成本约束：核心绘图、文件保存与导出不依赖收费绘图服务；如果现成服务需要付费才能满足核心需求，则自行建设。可优先评估免费开源基础，避免为免订阅而不必要地重写已有能力。

本文其余条目是上述方向下的建议规格，等待本次文档审核后冻结。产品名称、具体编辑器内核及框架不在本次定稿范围；本文件不构成开始编码的指令。

## 2. 核心价值与范围边界

用户希望减少照着截图重新画图的重复劳动，并能在 AI 与手工编辑之间反复切换。

“可编辑”必须包括对象身份与关系：文字可修改；节点可移动、缩放、改样式；连线连接到节点或连接点；分组可以整体移动。把整张截图作为一张背景图片放进画布，不算完成转换。

### 产品路线比较

| 路线 | 适配情况 | 主要取舍 |
| --- | --- | --- |
| 结构化图形编辑器（已选） | 流程图、架构图中的节点与关系 | 需要可靠的连线跟随、分组与文件语义 |
| 自由白板 | 自由摆放图片、文字与形状 | 流程关系需要额外约束 |
| 文本驱动绘图 | AI 生成结构描述、自动排版 | 手工布局与连线路径的精细编辑受限 |

### 首版不包含

账号与收费、云端同步、团队权限、多人实时协作、模板社区、移动端编辑、桌面安装包、内置 AI 聊天、模型账号托管、MCP 实时控制、独立知识库检索服务。

不承诺首版兼容 ProcessOn 私有文件或 Visio 文件；不把思维导图专用编辑、完整 UML/BPMN 语义、任意照片和网页截图转换纳入首版。

## 3. 主要用户流程

### 3.1 截图生成可编辑图稿

1. 用户首次使用时，按所用 AI 客户端的说明安装绘图 Skill 和配套工具。
2. 用户在外部 AI 中提供截图，指定忠实还原或重新排版，以及输出位置。
3. AI 读取与编辑器版本匹配的格式规范、图形目录与示例。
4. AI 识别文字、节点、连接方向、分组和大致位置，生成候选图稿。
5. AI 调用本地工具进行格式及关系校验；出错则依据对象 ID 和错误原因修复。
6. 工具渲染预览，AI 在客户端支持图像读取时核对预览与原图，必要时修改。
7. AI 交付图稿文件、预览和识别待核对说明；用户在本地网页打开图稿。
8. 用户修改、保存源文件，或导出 PNG、SVG、PDF。

预期日常指令：

> 使用绘图 Skill，把这张架构图按原布局转成可编辑文件；看不清的文字标记待核对，保存到指定目录。

第一次生成时编辑器页面可以不打开，文件生成与校验不依赖活跃浏览器会话。

### 3.2 人工编辑后再次交给 AI

1. 用户先保存当前图稿，将最新文件与修改要求提供给 AI。
2. AI 读取现有对象，保留未修改对象的 ID、内容与样式，仅调整需求涉及的部分。
3. AI 将结果保存为新文件，避免覆盖用户版本；校验并交付变更摘要。
4. 用户在编辑器中打开新文件检查；切换前如有未保存内容，先提示保存或放弃。

首版不监控外部文件实时变化，也不自动合并浏览器中未保存的修改。AI 只能处理明确提供或允许读取的最新文件，不能假定已看到当前画布。

### 3.3 成本与依赖要求

核心编辑流程需在本地完成，不以第三方绘图产品的免费额度、试用期或付费 API 作为必需条件。图形库、字体、导出组件和 AI 对接插件也要核实能否在这一前提下使用。优先验证 draw.io 的开源编辑器，Excalidraw 和 Eraser Diagrams 开源库可作为不同侧重点的候选；这不是已确认的最终选型。

外部 Codex/Qoder 或模型服务的账号、额度、API 费用属于独立成本，沿用用户已有工具；本产品不宣称这些 AI 调用免费。仅部署在用户电脑上可避免新增云服务器，但仍有开发与维护成本。

## 4. AI 对接方案：文件格式＋Skill＋工具

### 4.1 各部分的职责

| 部分 | 解决的问题 | 首版安排 |
| --- | --- | --- |
| 图稿文件规范 | 节点、连线、分组和样式如何描述与保存 | 必须提供，作为共同约定 |
| 格式 Schema | 字段类型、必填项、枚举、结构限制 | 必须提供，和格式版本绑定；按所选格式采用 JSON Schema、XSD 或相应规范 |
| 绘图 Skill | 何时读取规范、如何生成、校验、修复、交付 | 必须提供 |
| 参考资料与示例 | 图形用法、布局规则、正确与错误例子 | 随 Skill 分发，按需读取 |
| 本地校验与预览工具 | 确定性检查和实际渲染 | 必须提供；复用编辑器的文档处理规则 |
| 独立知识库/RAG | 检索大量企业资料或模板 | 首版不建设 |
| MCP | 读取当前文档、选区、增量修改并同步画布 | 后续阶段建设 |

Skill 是工作流说明，不是模型，也不是实时连接。知识库提供资料，本身不能让 AI 操作编辑器。首版的实际交换媒介是本地图稿文件；AI 使用宿主客户端已有的读写文件、运行工具和图像理解能力完成任务。

无需训练专用模型，也无需为编辑器接入独立大模型 API。用户仍通过所用 AI 客户端的账号与额度使用模型；不能据此承诺没有 AI 使用成本。若未来在网页内直接提供 AI 生成，则另行设计模型 API、密钥与调用成本。

### 4.2 AI 支持包的交付内容

以一份版本化源内容维护，针对 Codex、Qoder 分别提供安装说明或分发适配，避免两套规范独立演进。

- `SKILL.md`：触发场景、输入要求、两种模式的步骤、修改现有图稿的规则、错误处理与交付标准。
- 文件格式规范与对应 Schema：只读的数据约定；复用成熟格式时优先复用其官方规范。
- 图形目录：支持的形状、连接点、分组与样式能力。
- 少量完整示例：简单流程、条件分支、循环、多分组架构、带标注的连线。
- 校验与预览工具：对同一图稿输出一致的检查结果与视觉预览。
- 客户端安装与自检说明：确认 Skill 可被发现、能读取图片、能访问输出目录、能运行配套工具。

工具命令名、Skill 名称、正式文件扩展名在技术验证后确定。`.diagram.json` 仅表示自有 JSON 方案的候选文件名，不是现有行业标准；复用 draw.io 时优先验证其原生 `.drawio` 文件，无需为了 AI 对接额外设计一种文件格式。

### 4.3 生成和校验的边界

依次检查四层问题：

1. 格式：文档能按所选格式解析，字段符合对应 Schema，版本受支持。
2. 图结构：ID 唯一、连线端点存在、连接点有效、分组不成环、数值有效。
3. 渲染：文字、节点、线段能够显示，提示可检测的溢出和缺失资源。
4. 截图语义：AI 和用户核对文字内容、连线方向及分组归属；格式工具不能证明这些与截图一致。

自动修复最多执行三轮校验反馈。仍有硬错误时保留候选文件并明确标注未通过，列出失败原因，不交付“已完成”的错误结论。待核对的识别项不会阻止一个结构合法的文件打开。

对于不支持图片输入的模型或客户端，Skill 不能补齐视觉能力。首次自检应明确指出这一限制，并引导用户使用支持图片输入的配置；不承诺在未经测试的客户端版本上直接可用。

### 4.4 两种模式

| 维度 | 忠实还原 | 重新排版 |
| --- | --- | --- |
| 文字和关系 | 尽量忠于原图，不确定项显式标记 | 保留同样的文字、方向与关系 |
| 布局 | 保留相对位置、分组与主要连线路径 | 可调整位置、间距和连线路径 |
| 样式 | 尽量还原颜色、线型、字号及形状 | 可按选定主题统一样式 |
| 不允许 | 用整张截图冒充结构化转换 | 擅自增加、删减或改变业务语义 |

“忠实还原”是支持范围内的近似重建，不承诺任意截图像素级一致。无法识别的文字使用待核对占位并保留来源区域信息；未知关系不随意补造确定的连接。AI 的自报置信度不能当作准确率证明。

## 5. 编辑器功能规格

### 5.1 页面组成

- 顶部：文件名、未保存状态、新建、打开、保存副本、撤销、重做、导出。
- 左侧：基础图形与本地示例入口。
- 中间：可缩放和平移的画布，支持单选、框选和多选。
- 右侧：选中对象的文字、外观、尺寸、位置与连线属性。
- 可展开的核对面板：按对象定位识别疑点，用户修正后可标记已核对。
- 帮助入口：AI 使用指引、当前支持包与格式版本、常见文件错误说明。

首版不设内置 AI 聊天框。AI 发起位置在 Codex、Qoder 等客户端。

### 5.2 对象与操作

| 能力 | 首版要求 |
| --- | --- |
| 基础节点 | 矩形、圆角矩形、椭圆、菱形、圆柱体、文本框 |
| 文字 | 中文与英文、多行、字号、颜色、加粗、水平对齐 |
| 外观 | 填充色、边框色、边框宽度、实线与虚线 |
| 对象编辑 | 创建、删除、复制粘贴、移动、缩放、多选、前后层级调整 |
| 对齐 | 左右/上下/居中对齐、水平/垂直等间距分布、网格吸附 |
| 连线 | 直线、折线，起止箭头、线型、文字标签；可换端点、调整折点 |
| 连接关系 | 连接点绑定；移动或缩放节点后连线端点跟随，保留手调路径意图 |
| 分组 | 组合与解组、带标题容器、嵌套分组、整体移动与锁定 |
| 编辑恢复 | 撤销/重做；一次批量操作作为一个撤销步骤；单会话至少保留最近 100 步 |
| 辅助素材 | 可插入本地 PNG/JPEG 图标；支持移动、缩放，不承诺其内部内容可拆解 |

任意旋转、自由钢笔路径、复杂表格、海量厂商图标库、多页文档不纳入首版。循环边、并行边是合法结构，不能因流程图出现循环而判为错误。连接端点必须是受支持的节点或连接点，独立装饰线作为不同类型的对象保存。

删除节点时同步删除其关联连线，整个操作可撤销；删除非空容器时明确区分“解组并保留内容”和“删除容器及内容”。锁定对象不响应普通拖动与批量样式编辑。

## 6. 文件、保存与导出

### 6.1 原生文档的数据边界

必须采用有文档说明、可校验、可被 AI 读写并具有兼容策略的结构化文件。优先评估成熟的公开原生格式；只有验证表明现有格式或编辑器扩展能力不能满足核心需求时，才采用自有 JSON 文档。若采用自有文档，业务模型与具体编辑器内核的内部状态分离，避免把某个组件库的私有数据直接变成长期文件规范。下述数据能力是产品要求，不强制已有格式逐字采用同名字段。

文档包含：格式版本、文档 ID、修订信息、画布设置、节点、连线、分组、图像资源、样式及待核对记录。节点具有稳定 ID、位置、尺寸、类型、文字与连接点；连线引用节点 ID 与连接点，并保存折点、方向、标签及样式。

一个文件对应一个画布。资源内嵌或使用格式定义的封装方式，复制文件后可在另一目录正常打开；首版优先使用自包含文件，避免依赖机器上的绝对资源路径。原始截图默认不嵌入、不随导出传播；用户可另行提供用于核对。

识别核对信息引用对象 ID，区分“AI 提出”“用户已核对”；用户编辑对象后不会因重新保存而丢失状态。格式规范、Schema、工具与 Skill 明确标记兼容版本。

### 6.2 保存与重新打开

- 通用基础流程：选择本地文件打开，保存时生成可下载的完整图稿文件。
- 支持浏览器能力时可增强为授权后的直接写回；首版验收不依赖所有浏览器都能直接覆盖原文件。
- 明确区分“本地文件已保存”“浏览器恢复草稿”“有未保存修改”，不把恢复草稿冒充文件保存成功。
- 对编辑变更进行浏览器本地草稿缓存；刷新后提供恢复入口，清理浏览器数据可能导致草稿丢失。
- 切换文档前拦截未保存状态；关闭或刷新时尽力提示，但不承诺浏览器始终允许弹窗。
- AI 改稿默认输出副本；用户决定是否替换原稿。
- 未识别的主版本拒绝编辑，并保留原文件；不能静默丢弃未知图形后覆盖保存。

### 6.3 导出

| 格式 | 首版行为 |
| --- | --- |
| PNG | 整图或选区、1×/2×/3×、透明或指定背景、可配置边距 |
| SVG | 整图或选区，基础文字和图形保持矢量，嵌入图片仍为位图 |
| PDF | 单页适配整图，可设置边距；基础图形尽量保留矢量，中文显示必须验证 |

源文件是唯一保证编辑语义完整往返的格式。导出 SVG/PDF 不等于支持将它们完整导回为原生图稿。

缺失字体时明确使用替代字体并提示可能换行；正式验收包含中文、多行与混合字体。导出对象按边界计算，避免截断文字和箭头；超大分辨率先提示降低倍率或缩小选区。

## 7. 模块职责与依赖

| 模块 | 职责 | 输入与输出 |
| --- | --- | --- |
| 文档核心 | 文件解析、版本、对象模型、结构校验 | 原生文件 ↔ 合法文档/错误信息 |
| 编辑与渲染 | 画布交互、命中选择、样式、撤销 | 合法文档＋编辑命令 → 新文档＋画布 |
| 文件与草稿 | 导入、保存副本、草稿恢复 | 文档 ↔ 本地文件/浏览器缓存 |
| 预览与导出 | 一致渲染、PNG/SVG/PDF 输出 | 文档＋导出设置 → 预览/成品 |
| AI 支持包 | 指导外部 AI 生成、修复与改稿 | 截图/文档＋需求 → 经检查的文件 |
| 后续 MCP 适配 | 将受控编辑命令暴露给 AI | 文档查询/编辑请求 ↔ 当前编辑会话 |

AI 支持包依赖规范与工具，不依赖编辑器页面中的临时 UI 状态；预览工具与网页编辑器共享文档解释及渲染规则，避免预览正确、打开却不同。

上述是模块边界，不是微服务要求。首版以一套本地应用及配套工具交付，无需建立多个独立在线服务。

## 8. 异常与数据保护

| 情况 | 产品行为 |
| --- | --- |
| 文档无法解析/字段不合法 | 阻止导入；展示原因与对象/字段位置，允许复制诊断给 AI |
| 图结构错误 | 列出重复 ID、失效端点、分组循环等；不静默自动改动业务关系 |
| 不支持的图形或版本 | 明确拒绝或在不允许覆盖保存的预览中显示占位；保留原文件 |
| 模糊截图 | 可识别部分继续生成，疑点定位并标记，不伪装成准确识别 |
| 校验工具未运行成功 | 明确标注未校验，不能把候选文件称为验证通过 |
| 保存失败/空间不足 | 保留当前画布与脏状态，给出重试或保存副本入口 |
| 导出失败 | 保留源图稿，展示失败原因，允许降低尺寸后重试 |
| AI 基于旧稿修改 | 首版通过用户提供最新文件、默认输出副本降低覆盖风险；不承诺自动合并 |

文档按数据解析，不执行导入文件中的代码。对文件体积、对象数量及嵌入资源设置明确上限；首版建议总文件不超过 20 MB、总对象不超过 1,000 个，超限给出可理解的提示。导入的图像不自动从任意远程 URL 拉取。

编辑、保存、导出在本地完成，默认不上传图稿或截图。外部 AI 的截图上传和模型处理遵循该客户端自身的数据规则，不能将整个 AI 生成链路宣称为离线。

## 9. 验收标准与验证计划

以下是建议验收目标，不是已达成结果。开发前固定测试样本、客户端版本、模型配置和测试机器，保存每轮输入、输出与检查记录。

### 9.1 确定性能力：必须全部通过

1. 使用预先构造的合法文档验证全部首版图形、连线、分组与样式的打开、编辑、保存、重开，内容、关系和布局不丢失。
2. 移动/缩放节点后，连接关系保持；循环、并行边、嵌套分组和连线标签正常。
3. 删除节点及关联连线可一次撤销恢复；复制粘贴产生新 ID 且不会连接到错误的原对象。
4. 格式错误、失效端点、循环分组与不支持版本，均输出可定位诊断，不静默丢数据。
5. AI 改稿测试中未修改对象 ID 不变，修改范围外内容不变；保存副本可独立打开。
6. PNG、SVG、PDF 均验证中文、多行文本、透明度、虚线、箭头和内嵌图像；没有截断或缺失。
7. 断网情况下，已安装的本地编辑器及必要资源仍可打开、编辑、保存和导出；不包含外部 AI 生成。

### 9.2 AI 生成评估

建立 12 张固定样本：5 张流程图、5 张架构图、2 张包含模糊或遮挡的边界样本。流程图覆盖分支、循环和交叉线；架构图覆盖容器、分层、图标与双向连接。清晰样本建议每张包含 10–40 个主要节点。

Codex 与 Qoder 分别跑两种模式，记录客户端、模型及支持包版本。每个“客户端＋模型＋模式”组合独立评估，不把不同组合的结果混合计算。10 张清晰样本的建议首版目标：至少 9 张在最多三轮自动校验修复内生成合法可打开文件；以人工标注为基准，按该组合全部清晰样本汇总，节点和有向连线的精确率、召回率均达到 95%，可辨识文字字符准确率达到 98%。额外生成的节点/连线也计入错误；未成功生成的样本按对象和文字缺失纳入指标。

忠实还原另外逐图核对相对顺序、主要分组、主色和连线路径；重新排版核对没有改变业务关系、没有因重排隐藏文字或制造明显遮挡。对模糊项检查是否提示待核对，不能用格式校验替代识别效果验收。

这些目标需要通过样本验证可行性。若失败，记录原因并调整模型配置、支持范围或交互提示，由用户确认范围变化；不静默降低标准。

### 9.3 性能基线

建议在当前开发电脑、记录版本的 Chrome 上，以 200 个节点＋300 条连线的固定文档测量：首次打开不超过 3 秒，常规操作反馈不超过 100 毫秒；导出 2× PNG 与单页 PDF 分别不超过 10 秒。记录测试机器与实际数字，AI 生成耗时单独统计，不混入编辑器性能指标。

本次只完成文档检查和公开能力核实，尚未运行上述产品测试。

## 10. 后续 MCP 阶段

目标：用户在 AI 中说“把当前选中的模块移到右边，再增加一条连接”，AI 可以操作当前画布。

建议链路：外部 AI 客户端 → 本地 MCP 服务 → 编辑器的文档命令接口 → 浏览器更新画布。

提供的能力包括读取当前文档及修订号、读取选区、查询对象、提交一批修改、校验、获取预览、保存与导出。具体工具名在该阶段设计。

所有修改附带文档 ID 与预期修订号；当用户已继续编辑，旧修订请求应拒绝并要求重新读取。一次批量修改要么全部生效，要么全部失败，且作为一次撤销操作。预览应返回实际应用后的状态。

服务限定明确授权的文档或工作目录；对本地 HTTP 通道进行来源校验与认证，避免仅因监听本机端口就允许任意网页操作文件。MCP 的连接、会话选择与同步机制属于独立阶段，不因客户端支持 MCP 就自动具备。

Skill 在这一阶段继续负责绘图规则和工作流，MCP 负责可调用的读取与修改能力。文件规范仍是保存与迁移基础。
