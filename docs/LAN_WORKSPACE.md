# 局域网共享工作区 · v1.2.1

本版支持多人查看同一份图稿、单人持有编辑锁、自动保存和其他页面自动更新。每份图稿有独立地址，保存在运行服务的电脑上；不提供多人同时修改同一画布的实时合并。

## 启动与加入

本版最低要求 Node.js 22.22，推荐 24 LTS。共享存储使用 Node 内置 SQLite，版本下限与本轮实测环境保持一致。

在服务电脑安装依赖、完成构建后运行：

```sh
npm run build
node bin/zhitu.mjs --lan-host 192.168.1.10 --port 4317 --editor-port 4318
```

将 `192.168.1.10` 替换为服务电脑实际的局域网 IPv4 地址或内网主机名，不要填写 `0.0.0.0`。工作台和独立画布分别使用 4317、4318 两个端口，需允许局域网访问。建议为服务器固定地址。所有人打开同一个 `http://192.168.1.10:4317/`；其他电脑上的 `127.0.0.1` 指向其他电脑自身。

首次打开只需填写用户名，无需密码或访问码。同一浏览器、同一地址会自动记住身份，不会定期要求重新登录。在文件库点击“修改用户名”可以改名，文件归属不变。

用户名是显示名称，不是真实身份认证。换浏览器、换访问地址或清理站点数据后需要重新填写，并获得新身份；填写相同用户名不会接管旧身份或旧 AI 任务。共享文件仍在文件库中，旧身份创建的文件可由本机管理员删除或恢复。任何能访问这个可信局域网地址的人都可以填写名称加入。

升级前仍有效的浏览器会话会保留原身份，旧密码和访问码停止使用。旧数据库的 `accounts`、`settings` 表保留但不再读取；新工作区不再创建这两个表。

不传 `--lan-host` 时仍只监听本机，主页变为文件库，并以本机管理员身份打开。`/local` 保留原有临时画布和示例。局域网模式下，服务电脑打开 `http://127.0.0.1:4317/` 自动进入本机管理员界面；通过局域网地址访问则作为普通成员加入。管理员身份只向本机请求提供，旧远程管理员会话转为成员。现有浏览器草稿不会自动上传：可先在临时画布恢复，再点击“保存到共享文件库”。

可用 `--data-dir /绝对路径/团队图稿` 指定持久化目录；默认是服务电脑上的 `~/.ai-zhitu`。服务需保持运行。局域网 HTTP 适用于可信内网，传输未加密；本版不含公网部署、TLS 终止或租户隔离。

## 文件与编辑

1. 主页“文件库”支持新建、导入 `.drawio` / XML、按名称搜索和回收站。列表分别显示“创建人”和“最后保存人 / 时间”；创建人记录保留，不随他人修改而变化。
2. 打开后地址为 `/documents/<文档ID>`，默认只读。点击“分享链接”立即打开分享窗口并尝试复制，窗口会明确显示复制结果；浏览器不允许自动复制时，可选中窗口中的链接手动复制。接收者首次填写用户名进入同一工作区。
3. 点击“获取编辑权”。每份文档只有一个标签页能编辑，即使两个页面使用同一个浏览器身份也不能同时编辑。不同文档可以由不同人同时编辑。
4. 修改图形或顶部名称后，每约 2 秒自动保存；也可点“保存到服务器”。服务器版本号和保存状态显示在画布上方。保存后，其他只读页面约 2 秒内加载新内容。
5. 点“结束编辑”会先保存当前修改再释放锁。关闭页面尝试立即释放；断网、崩溃或设备休眠后，最多等待最后一次续约后 30 秒即可接管。

“新建”“打开”“本地示例”在共享图稿中会创建另一份共享文档，不覆盖原文档；导入每次都会分配新的文档 ID。文件名用于显示，重命名不会改变分享链接。

“保存副本”和“保存到文件”是下载或写入访问者自己的磁盘，不替代服务器保存，不会清除共享文档的未同步状态。HTTP 局域网环境通常不提供直接写文件 API，此时自动退回下载副本。导出 PNG、SVG、PDF 仍然可用。

## 断线、冲突与恢复

- 心跳失败或编辑锁到期后，页面暂停编辑并保留当前内容，不自动用远端版本覆盖未同步修改。浏览器恢复草稿仍是辅助恢复手段。
- 恢复联网后，可以重新获取编辑权。如果服务器版本没有变化，可继续保存当前修改；如果别人已保存新版，系统拒绝覆盖。
- 冲突时先点“保存副本”下载未同步图稿，再点“加载最新版本”。放弃未同步修改前有确认。需要合并时，可将备份导入为另一份图稿，手动整理。
- 刷新正常已保存的文档会重新打开同一地址；刷新前仍有未同步修改时，应先下载副本或使用恢复草稿。
- 每次内容或名称变化的保存会生成服务器版本，保留每份文档最近 50 版。无变化的重复保存不增加版本。恢复历史版本需要编辑权，并产生新的版本；恢复前会先保存当前未保存内容。
- 创建者或管理员取得编辑权后可以将文档移入回收站。同一创建者或管理员可以从回收站恢复。没有永久删除入口。

## AI 使用

服务器管理员在设置中配置并登录服务器上的 Codex/Qoder CLI。团队成员使用这台服务器的 AI 客户端和额度，而不是自己电脑上的 CLI。

- 只有管理员可修改客户端路径、检测或测试连接。
- 每个浏览器身份只能查看、接回和取消自己发起的 AI 任务；共享文档内的最近任务按文档过滤。
- 修改共享图稿前需要编辑权，候选应用同样受画布只读限制。AI 结果不会绕过服务器版本检查。
- AI 请求按进入顺序执行，同一服务最多一个正在执行，运行和等待总计最多 8 个任务。取消排队任务不会调用模型。
- 结束编辑不自动取消已提交的 AI 请求；候选仍属于提交者。重新应用需再次获得编辑权，并核对候选基线。
- AI 任务与队列是内存状态，服务重启后清空。需要保留的候选请下载，或应用并保存到共享文档。

## 数据位置与备份

| 数据 | 位置 |
| --- | --- |
| 文档、服务器版本、回收站、浏览器身份会话、编辑租约 | 数据目录的 `workspace.sqlite` |
| SQLite 正在运行的事务日志 | 同目录 `workspace.sqlite-wal` / `workspace.sqlite-shm` |
| AI 客户端配置 | 同目录 `clients.json` |
| 恢复草稿、本地版本和最近颜色 | 各访问者的浏览器存储 |
| AI 任务和导出任务 | 服务内存与临时文件 |

最简单的完整备份方式：正常停止服务，复制整个数据目录，再启动服务。恢复时停止服务，将备份目录作为 `--data-dir` 启动。不要在服务运行时只复制 SQLite 主文件，可能漏掉 WAL 中已提交的内容。备份包含浏览器身份和访问凭据，应按团队数据管理。

共享模式没有每文档私密权限：所有已加入成员都能查看和申请编辑所有共享图稿。删除/恢复仅限创建者或管理员；精细权限、文件夹和实时合并不属于本版能力。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 同事打不开页面 | 检查地址是否为服务器内网 IP，确认端口、防火墙和服务状态 |
| 文件库能打开但画布加载失败 | 检查第二个画布端口是否允许访问；分享同一个配置的主机名 |
| 无法获取编辑权 | 查看谁在编辑，请对方结束编辑；异常断线后等待租约到期 |
| 已保存内容没更新 | 检查网络状态、当前页面是否保留了未同步修改；必要时先下载再加载最新版本 |
| 改端口或换浏览器后草稿不见 | 草稿是浏览器本地数据；共享文档仍可在服务器文件库找到 |
| AI 排队 | 等待先前任务结束，或取消自己的排队任务 |
| 重启后编辑锁短暂存在 | 租约在数据库中保存，最后一次续约后 30 秒自然失效 |

实现和测试入口见 [技术设计](design/TECHNICAL_DESIGN.md) 与 [v1.2.1 身份简化验证报告](testing/V1_2_1_IDENTITY_REPORT.md)。
