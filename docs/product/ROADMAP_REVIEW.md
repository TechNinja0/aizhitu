# 产品功能重整：以画布内 CLI 对话为下一阶段主线

日期：2026-09-18。本文根据用户新增的“画布内通过已配置 CLI 生成/修改图稿”及随后“重新分析是否还需要 P2”制定，覆盖旧清单的后续优先级。v1.0 已交付能力与验收记录保持不变。本文是下一阶段范围决策和讨论稿，不代表会话功能已经实现。

## 1. 结论

不再把 P1/P2 当作必须逐项清空的交付包。下一阶段聚焦“一键美化＋画布内 AI 对话＋可靠修改审阅”。旧 R19 中对用户有价值的能力并入 AI 对话；MCP 降为可选外部接口。旧 R20 必须拆分判断，不能把代码分析、新图稿和多页捆绑实施。

产品定位从“AI 在外部生成文件、用户再导入”扩展为“本地可编辑图稿工作台，在同一个页面内调用用户已有 CLI 完成生成与改稿”。外部 Skill/文件交换仍是兼容入口。

## 2. 产品能力、交互入口和实现机制分开

- **产品能力**：生成可编辑图、理解当前图稿和选区、局部改稿、核对、撤销与导出。
- **交互入口**：网页内聊天、外部 Codex/Qoder 对话、直接手工操作。
- **实现机制**：CLI 子进程、原生文件快照、内部图稿接口；未来可选 MCP。

“实时修改”不等于“必须 MCP”。网页可以通过本地服务启动 CLI，把当前未保存图稿和选区快照交给它，再把结果校验、比较并应用。反过来，接入 CLI 并不自动获得撤销、冲突检测或正确的连线，这些仍由工作台负责。

## 3. 新优先级

| 能力 | 与第 3 项的关系 | 决策与理由 |
| --- | --- | --- |
| 一键美化、去短折线 | 独立的确定性编辑能力 | 保留并优先；不需要每次消耗 AI，保持文字、对象和语义关系不变 |
| 网页内 AI 对话，选择 Codex/Qoder | 核心入口 | 下一主线；沿用客户端账号和配置，不另建模型账号体系 |
| 当前图稿/选区快照、稳定对象 ID | 对话必须的上下文 | 从旧 R19 提升为主线基础能力，不能依赖磁盘旧副本 |
| 候选预览、对象差异、版本冲突、一步撤销 | 对话必须的可靠修改能力 | R16 与旧 R19 合并实现一套图稿变更服务；手工导入候选也复用 |
| 直接保存、嵌入源图稿的 PNG/SVG | 独立文件体验 | 保留为文件增强，优先级低于对话闭环；下载副本继续兜底 |
| MCP 控制当前画布 | 外部 AI 的标准接入机制 | 暂缓；网页内对话首版不以 MCP 为前置。不同时维护两条修改流程 |
| 从代码库生成架构图 | CLI 对话的输入场景 | 复用 CLI 理解用户明确选择的仓库；不另造多语言代码分析引擎 |
| 思维导图、组织结构图 | 多数可用现有节点/连线表达 | 作为后续生成说明、模板和布局规则扩展；没有必要另造编辑器 |
| 时序图 | 需要专门验证生命线、消息与相对顺序 | 后移为独立类型增强；不能只换一个提示词就声称编辑语义完整 |
| 多页文件 | 文档组织能力，CLI 无法替代 | 暂缓；不阻塞单画布对话。需要统一页面身份、撤销、草稿、差异、导出与版本兼容后再交付 |
| Mermaid 导入 | 确定性的可编辑格式转换 | 保留后续，可离线使用；先明确语法子集和不支持内容，不用 AI 转换冒充稳定解析器 |
| 个人组件/模板、更多图形 | 编辑效率增强 | 按实际复用场景迭代，排在核心对话之后 |
| 复杂 UML、BPMN、多人协作 | 不属于当前核心场景 | 继续排除；此前确认的新类型意向保留，但不要求与下一版本一起交付 |

## 4. 推荐的网页内 AI 流程

1. 首次选择/检测本机已安装 CLI；展示可用版本、登录/执行能力与工作目录。只读检查，不替换用户配置或自动升级全局工具。
2. 聊天框接受文字和截图。用户可选择“修改当前图”“基于选区修改”或“生成新图”；仓库路径由用户明确选择。
3. 发送时结束正在编辑的文字，截取完整原生图稿、选区 ID、文档身份、修订号和必要图片。取当前画布，不假定已保存磁盘文件是最新版。
4. 本地服务在单次任务目录中调用选定 CLI。工作台管理会话历史；每轮都带最新图稿，避免对话沿用过期画布。首版不接管用户在终端中已有的对话。
5. CLI 返回候选 `.drawio` 及说明；工作台执行确定性校验、渲染和对象差异比较。可修复的错误最多自动反馈三轮。
6. 推荐先预览候选与修改摘要，再由用户点击“应用”；应用为一次可撤销编辑。如果用户在等待期间修改了图稿，旧候选不能直接覆盖，需要重新生成或重新比较。
7. 失败、取消、客户端退出或超时均保留当前画布。提供明确的任务状态和有边界的日志，不把 CLI 原始内部输出全部展示给用户。

“实时”在首个对话版本中定义为能读取当前画布并回填候选，不要求把模型逐 token 产生的不完整图形实时写进正式画布。

## 5. 责任边界

| 工作台负责 | 已有 CLI 负责 |
| --- | --- |
| 当前图稿与选区、任务生命周期、输入快照 | 自然语言理解、截图识别、代码理解、推理 |
| 图稿校验、连线规则、原图核对、预览与导出 | 在授权的任务/仓库范围内生成候选原生文件 |
| 差异、冲突检测、原子应用、撤销、草稿和保存 | 按工作台反馈修复候选并解释改动 |
| 进程启动/停止、会话关联和错误展示 | 使用用户已经配置的客户端账号、模型和额度 |

一键美化属于工作台的确定性能力。AI 可以建议或调用这一能力，但不应重新实现一套无法稳定复现的短折线修复算法。

## 6. 技术方向与边界

推荐“网页 → 本地任务服务 → CLI Provider 适配器 → 候选文件 → 图稿变更服务”。本机已安装的 Codex/Qoder 命令帮助已只读检查，具备非交互调用与机器可读输出相关选项；实际流式事件结构、权限等待、取消与版本差异仍需实现契约测试。

- 不在浏览器里执行任意 shell 命令；后端使用固定适配器、明确参数数组和 `shell:false`。
- 不读取或复制 CLI 密钥；复用客户端登录环境。不能将此描述为“AI 免费”，费用仍取决于用户客户端。
- 不默认使用跳过权限或取消沙箱的参数。CLI 专注生成任务目录中的候选，预览由工作台自己的渲染服务执行，避免要求 AI 子进程额外监听端口。
- 如果客户端需要额外权限而非交互任务无法回答，任务显示“需要处理权限”，不能偷偷提升权限或无限挂起。
- 引入统一的 `snapshot / validate / diff / apply(expectedRevision) / undo` 内部契约。未来 MCP 是这套能力的适配层，不再复制一套文档写入实现。
- 截图上传至所选 CLI/模型属于外部 AI 请求；本地编辑、校验和导出继续本地运行。文件增强的“嵌入源图稿”必须明确告知分享图片也会分享源文件。

## 7. 实施顺序与完成条件

### 阶段 A：编辑基础增强

一键美化、差异比较、按修订应用、一步撤销；已有文件增强按定向测试收敛。通过带分组、锚点偏移、遮挡、锁定和人工折点的真实内核测试，不改变未涉及对象。

### 阶段 B：单画布 CLI 对话闭环

先打通一个 Provider 的“生成 → 校验 → 预览 → 应用 → 撤销”，再接第二个 Provider。发送期间继续手工编辑、取消请求、CLI 退出、权限不足、无效候选与过期基线都必须实测。后续用户已接受推荐方案，采用先预览、再手动应用。

### 阶段 C：按实际需要扩展

仓库输入场景与轻量模板优先。多页、时序语义和 Mermaid 导入分别有独立规格与验收。只有明确需要“在外部 Codex/Qoder 中直接控制已打开画布”时，再实现 MCP 入口。
